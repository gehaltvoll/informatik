Die Idee

Ein Fingerabdruck ist viel kleiner als ein Mensch und passt doch nur zu dieser einen Person. Aus dem Abdruck lässt sich die Person aber nicht rekonstruieren. Ein Hash funktioniert gleich: Er kennzeichnet Daten, verrät aber nichts über ihren Inhalt.

Eingabebeliebig lang: ein Wort, ein Foto, ein Film
→
Hashfunktionrechnet nur in diese Richtung
→
Hashimmer gleich lang, bei SHA-256 sind es 256 Bit

Das Wort kommt vom englischen to hash, zerhacken. Die Daten werden so stark zerhackt und durchmischt, dass aus dem Ergebnis nicht mehr auf die Eingabe zu schliessen ist.

Wozu braucht man das?

Mit einem Hash lässt sich prüfen, ob zwei Dinge gleich sind, ohne sie selbst anzuschauen.

Stellen Sie sich zwei dicke Bücher vor. Sie möchten wissen, ob sie Wort für Wort gleich sind. Von Hand dauert das Tage. Hat jedes Buch einen kurzen Fingerabdruck, genügt ein Blick: gleicher Abdruck, gleiches Buch.

Finden Sie den Unterschied

Diese zwei Texte unterscheiden sich in genau einem Buchstaben. Sehen Sie ihn? Der Hash zeigt es sofort. Ändern Sie die Texte ruhig selbst.

Der Hash hat zwei Vorteile: Er ist immer kurz, und er verrät den Inhalt nicht. Darum steckt er in vielen Diensten, die Sie täglich nutzen.

Ein Hash von Hand

Eine echte Hashfunktion ist zu lang zum Nachrechnen. Darum beginnen wir mit einem Spielzeug-Hash, der in eine Zeile passt. Jedes Zeichen hat einen Zahlencode (zum Beispiel A = 65). Der Zwischenwert h startet bei 7 und verarbeitet ein Zeichen nach dem anderen:

h = (h × 31 + code) mod 256

mod 256 bedeutet: der Rest beim Teilen durch 256. So bleibt h immer zwischen 0 und 255 und passt in 8 Bit, egal wie lang die Eingabe ist.

Spielzeug-Hash Schritt für Schritt

Warum die Multiplikation mit 31? Würden wir nur die Codes addieren, hätten AB und BA denselben Wert. Durch die Multiplikation zählt auch die Reihenfolge: AB ergibt , BA ergibt .

def spielzeug_hash(text):
    h = 7                              # Startwert
    for zeichen in text:
        h = (h * 31 + ord(zeichen)) % 256
    return h

print(spielzeug_hash("HASH"))

Kollisionen suchen

Eine Kollision liegt vor, wenn zwei verschiedene Eingaben denselben Hash ergeben. Der Spielzeug-Hash hat nur 256 mögliche Werte. Dieses Labor erzeugt zufällige Fantasiewörter, bis zwei davon denselben Wert haben.

Schubfachprinzip Spätestens beim 257. Wort muss sich ein Wert wiederholen, denn es gibt nur 256 Schubfächer. Im Durchschnitt passiert es schon nach rund 20 Wörtern, weil jedes neue Wort mit allen bisherigen kollidieren kann. Kollisionen lassen sich bei keiner Hashfunktion ganz vermeiden: Es gibt unendlich viele Eingaben, aber nur endlich viele Hashes.

Das echte Werkzeug: SHA-256

SHA-256 folgt derselben Grundidee: Ein Zwischenwert nimmt die Daten Stück für Stück auf. Die Daten werden in Blöcke von 512 Bit zerlegt. Jeder Block durchläuft 64 Runden, in denen Bits verschoben, gemischt und addiert werden. Am Ende bleiben 256 Bit übrig.

In Python steht SHA-256 im Modul hashlib bereit. Die Funktion arbeitet mit Bytes, darum wird der Text zuerst kodiert:

import hashlib

text = "Hallo Klasse"
daten = text.encode("utf-8")
print(hashlib.sha256(daten).hexdigest())

Wie sicher ist «Einweg»?

Angenommen, ein Computer probiert eine Milliarde Eingaben pro Sekunde. Um alle 2256 Werte durchzugehen, bräuchte er rund 3.7 × 1060 Jahre. Das Universum ist etwa 1.4 × 1010 Jahre alt.

Hashfunktionen altern trotzdem. MD5 und SHA-1 gelten als gebrochen: 2017 wurde eine echte SHA-1-Kollision veröffentlicht. Für das vollständige SHA-256 mit 64 Runden ist keine Kollision bekannt. Die besten Forschungsarbeiten von 2026 erreichen Kollisionsangriffe auf gekürzte Versionen mit 38 Runden.

Anwendung: Passwörter speichern

Ein Login muss nur prüfen, ob die Eingabe stimmt. Dafür muss der Server das Passwort gar nicht kennen. Er speichert einen Hash und vergleicht beim Anmelden die Hashes. Doch was passiert, wenn die Datenbank gestohlen wird? Gehen Sie die drei Stufen durch. Alle Konten sind erfunden.

Datenleck in drei Stufen

Der Angreifer besitzt eine fertige Tabelle mit den Hashes von 20 häufigen Passwörtern und vergleicht sie mit der gestohlenen Datenbank.

Salt Ein Salt ist eine zufällige Zeichenfolge pro Konto, die vor dem Hashen an das Passwort gehängt wird. Er ist nicht geheim und liegt offen in der Datenbank. Seine Aufgabe: Gleiche Passwörter ergeben verschiedene Hashes, und vorberechnete Tabellen werden wertlos. Der Angreifer muss für jedes Konto einzeln rechnen.

Anwendung: Dateien prüfen

Wer eine Datei herunterlädt, möchte wissen, ob sie unverändert angekommen ist. Viele Anbieter veröffentlichen dazu den Hash, die sogenannte Prüfsumme. Stimmt der selbst berechnete Hash damit überein, ist die Datei Bit für Bit identisch.

Die Grenze Eine Prüfsumme hilft nur, wenn sie aus einer vertrauenswürdigen Quelle stammt. Kann ein Angreifer Datei und Prüfsumme gemeinsam austauschen, fällt nichts auf. Dagegen helfen digitale Signaturen, die ebenfalls auf Hashes aufbauen.
